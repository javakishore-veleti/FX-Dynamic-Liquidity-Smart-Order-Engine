# AWS deployment for fx-topology-service

Deploys the topology service to AWS with CloudFormation, driven by manual GitHub Actions runs.

## Stacks (CloudFormation, `CICD/AWS/cfn/`)

| Order | Template | Stack name | Creates |
|---|---|---|---|
| 1 | `01-network.yaml` | `fx-topology-network` | VPC and two public subnets, or reuses a VPC. Security groups for load balancer, service, and database |
| 2 | `02-data.yaml` | `fx-topology-data` | RDS PostgreSQL, password managed by Secrets Manager |
| 3 | `03-ecr.yaml` | `fx-topology-ecr` | ECR repository for the image |
| 4 | (image build) | — | Maven jar, Docker image, pushed to ECR |
| 5 | `04-compute.yaml` | `fx-topology-compute` | ECS Fargate service, Application Load Balancer, logs |

## Workflows (`.github/workflows/`)

| Workflow | Does |
|---|---|
| `AWS-0100-Setup-All` | Runs all setup workflows in order |
| `AWS-0100-Destroy-All` | Runs all destroy workflows in reverse order |
| `AWS-0001-Setup-network` | Network stack. Input `use_existing_vpc` (`no` default) |
| `AWS-0001-Setup-data` | Database stack |
| `AWS-0001-Setup-ecr` | Registry stack |
| `AWS-0001-Setup-app` | Builds the jar and image, pushes to ECR |
| `AWS-0001-Setup-compute` | Service and load balancer |
| `AWS-0001-Destroy-compute` / `-data` / `-ecr` / `-network` | Each deletes its stack. Requires `confirm` = `DESTROY` |

## GitHub secrets

| Secret | Required | Notes |
|---|---|---|
| `AWS_ACCESS_KEY_ID` | Yes | IAM user or role with rights to CloudFormation, EC2, ECS, ECR, RDS, ELB, IAM (for the task role), Logs, Secrets Manager |
| `AWS_SECRET_ACCESS_KEY` | Yes | |
| `AWS_REGION` | Yes | For example `eu-west-1` |
| `VPC_ID` | Only with reuse | Existing VPC id |
| `REUSE_PUBLIC_SUBNET_A` | Only with reuse | Public subnet in one availability zone |
| `REUSE_PUBLIC_SUBNET_B` | Only with reuse | Public subnet in a second availability zone |

## Notes

- The database password is generated by RDS and kept in Secrets Manager. It never appears in a template, parameter, or log.
- Destroying the data stack deletes the database and its data.
- Reusing a VPC means the network destroy leaves that VPC in place.
- Kafka is off in AWS (`FX_FEATURES_KAFKA_ENABLED=false`). No managed Kafka is created.
- Nothing runs in AWS until the owner approves the cost and creates the secrets.
