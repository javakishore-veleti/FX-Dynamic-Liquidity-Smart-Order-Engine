1. Overview

Service port 8081 · dedicated database fx_quote_db (H2 default / Postgres with local-postgres)

In everyday terms: this service answers “What price can we show a customer right now for EUR/USD (or another pair)?” It combines a market mid-price with the bank’s fee rules, then sends those prices to screens and APIs.

2. Plain-language glossary

Quote

A quote is a priced offer for exchanging one currency for another (for example EUR/USD). In this codebase it is not a final trade yet — it is the rate the system is willing to show a client at that moment (bid/ask or an indicative client rate), usually including the bank’s fee.

Markup

Markup is the bank’s fee added on top of the raw market price. It is commonly measured in basis points (bps): 1 bps = 0.01%. Example: if the market mid is 1.1000 and markup is 10 bps, the client may see a worse rate by about 0.0010 — that gap is how the bank earns on the FX deal.

Client tier

Clients are grouped into pricing levels such as Tier 1 / Tier 2 (large corporates vs smaller clients). Better tiers usually get a smaller fee.

Client-tier markup schedules

A lookup table that says: “For this client tier + currency pair + market session, charge this fee.” Example row meaning: Tier 2, EURUSD, London/NY overlap → markup 1.5 bps. That is what table client_tier_spread_schedules stores.

Common-man picture: like airline fare classes. Same flight (same EUR/USD market), but Business vs Economy (Tier 1 vs Tier 2) pay different add-ons. The schedule is the published price list by class, route, and time of day.

Indicative (indicative quote)

Indicative means “for guidance / estimate only” — not a firm, binding commitment to trade. An indicative quote answers: “About what rate would we show you right now for this pair, amount, and client tier?” The client can use it to decide, but the bank is not yet locked into executing at that exact rate. Firm trading comes later (qualify → route-exec). In this API that is POST /api/v1/fx/quotes/indicative — one request, one answer (unlike the continuous live stream).

Common-man picture: asking a car dealer “roughly what would this model cost today?” before you sign a purchase contract. Helpful and current, but not the final signed deal.

Corporate vs retail flows

Same quote engine underneath; different who and how in the UI:

  • Corporate flow (Corporate portal :4202) — company treasury / dealing-desk style: larger notionals, blotters, credit/qualify checks, multi-LP execution language, often better tiers / tighter markup.
  • Retail flow (Retail portal :4203) — consumer / small-business style: convert money, planner, simpler screens, usually smaller amounts and a wider retail markup.

So “indicative quote API for corporate/retail flows” means: both portals can call the same “give me an estimated FX price” API; each flow just wraps it in a different user journey.

Live quote

A price that is current right now, not a stale printed rate from earlier. FX prices move continuously; a live quote is the latest tick the service has for a pair (and tier).

Live quote stream

A continuous feed of live quotes over time (tick, tick, tick…), so a screen can update without the user clicking Refresh. In this service that feed is exposed as GET /api/v1/fx/quotes/stream.

SSE (Server-Sent Events)

A simple web technology where the server pushes updates to the browser over one HTTP connection. Think of it like a one-way live news ticker from server → browser. It is lighter than WebSockets when you only need the server to talk and the client to listen.

Portal

In this project, a portal is a web UI people use in the browser: Admin (:4201), Corporate (:4202), or Retail (:4203). Portals call middleware APIs (like this quote service) and display the results.

Blotter

A trading/operations screen that shows a list of live market or order activity in rows — pairs, prices, sizes, status — similar to a live spreadsheet for the desk. Historically a “blotter” was the paper pad traders wrote deals on; digitally it is that live list UI.

Portal blotter

The blotter screen inside one of the portals. Example: the Corporate portal blotter page listens to the SSE live quote stream so currency rows update automatically as new quotes arrive.

Putting the phrase together: “SSE live quote stream for portal blotters” means “a server-pushed feed of current FX prices that the web trading screens use to keep their price tables up to date.”

3. Business features

  • Push current FX prices to web screens (portal blotters) over SSE
  • On-demand indicative (non-binding estimate) quote used by both Corporate and Retail portals
  • Fee rules by client tier, pair, and market session (cached for speed)
  • Spot mid-rate lookup by currency pair

4. Database tables

Database: fx_quote_db (H2 default / Postgres with local-postgres)

  • client_tier_spread_schedules — the fee price list: which markup (in bps) applies for a given client tier, currency pair, and session.
